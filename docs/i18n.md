# Frontend i18n

M4 起前端使用 `i18next` + `react-i18next`，不要等 M9 再补，避免字符串散落在组件里。

## 结构

```
ui/src/
├── i18n.ts                 # 初始化、语言检测、setLanguage()
└── locales/
    ├── en.json
    └── zh-CN.json
```

- `i18n.ts` 初始化 `i18next`，资源内置为 en / zh-CN。
- 首次启动读取 `localStorage["octos.language"]`；没有则按 `navigator.language`（zh* → zh-CN，否则 en）。
- Settings 的“界面语言”下拉调用 `setLanguage()`，立即切换并写入 localStorage。
- 组件统一用 `const { t } = useTranslation()`，key 按 `nav.* / library.* / settings.* / bridge.* / common.* / footer.*` 命名。
- 文案 key 必须在 en/zh-CN 两份 JSON 中同时存在；缺失时回退 en。

## 约定

- **Rust 不返回界面文案**。IPC 返回错误码/结构化错误，前端用 key 翻译；日志保持英文。
- **mod 作者提供的 label/description 不自动翻译**。它们是内容，不是 UI chrome；后续可支持 mod 自带 `locale/zh-CN.json`。
- **原生托盘菜单**暂时英文；后续与前端共用一份 locale 或从 UI 下发。
- 日期/时间用 `Intl.DateTimeFormat(i18n.language)`，不要硬编码 locale。
- 新增语言：加 `src/locales/<tag>.json`、注册到 `i18n.ts`、在 Settings 下拉加一项；用 key parity 检查缺失。
- 测试：`npm run typecheck` + `npm run build`；建议后续加 locale key parity 单测。
